# CAGE × VEIP v0.1 — sample warrant-reliance evidence

Generated by `generate_samples.py`, which drives the CAGE code path (`bootstrap_governor` with the finance plugin, EU_ECB thresholds, the gateway `/governance/validate-action` endpoint, the trade tool, and a hash-chained evidence stream).

**Caveats**
- Warrants come from a seeded `Provider05WarrantSource` holding the VEIP v0.1 vectors verbatim. Nothing went over the wire to VEIP.
- Development posture with a hermetic test key. The seal HMAC is redacted, and the preview envelope is unsigned because no KMS key is configured. Signatures are illustrative only.
- Warrant authenticity is **UNVERIFIED** (issuer signatures arrive in VEIP v0.2; POAM-2026-104). The digest proves internal consistency, not who issued the warrant.
- The clock is fixed at 2026-08-22T12:00Z. Only the processing time `latency_ms` changes between runs.

**Files**
- `vec001_allow.json`: VEC-001 (ACTIVE), confidence 0.98 (floor is 0.97). The result is ALLOW. The file contains the v3.0 `GovernanceEnvelope` preview response (whose top-level `external_attestations` WARRANT entry matches the sealed `RelianceRecord` field for field) and the seal's `GOVERNANCE_DECISION` record. `record_hash_computation` recomputes `SHA-256(prev_hash ‖ JCS(header) ‖ payload_json)`. `payload_json` includes the full 64-hex `params_hash` and warrant digest `b30bcf…1fce`, and the seal's third field is that `record_hash`.
- `vec002_defer.json`: VEC-002 (REVOKED). The result is DEFER with `WARRANT_INELIGIBLE` / `RELIANCE_INELIGIBLE_REVOKED`. The HTTP 200 preview response is wrapped in a v3.0 `GovernanceEnvelope` whose `payload` carries the `DeferToken`, structured `Violation` dicts (`tier`, `code`, `message`, `verdict`, `control_id`), and ineligible `RelianceRecord`. Both the preview and the commit attempt (`DEFERRED:`) park a token and write a `GOVERNANCE_DEFERRAL` record (`control_id: "CTRL_AGT_001"`, full 64-hex `params_hash`). There is no refusal, seal, or actuation.
- `vec006_tampered_defer.json`: VEC-006, where the declared digest does not match the content. The result is DEFER with `INELIGIBLE_UNRESOLVED`, and `reason` records both full digests.
- `missing_defer.json`: no warrant is published. The result is DEFER with `INELIGIBLE_MISSING`; the warrant fields are empty.
- `vec002_post_hitl_retained.json`: a human approves a 0.96 trade, then the issuer revokes the warrant. The result is DEFER with `approval_retained=true`. After the warrant is restored, the same approval redeems: ALLOW, sealed and executed once, and a replay is blocked.

**Where the VEIP evidence fields are.** The same keys appear in the chained `reliance` record (`GOVERNANCE_DECISION` and `GOVERNANCE_DEFERRAL`), in `envelope.payload.reliance` on `DEFER`, and in `envelope.external_attestations[0]` on `ALLOW`.
