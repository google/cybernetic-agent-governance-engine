## [Unreleased]

### Added

- **CI runs `terraform test` against the gcp-gke target** (`ci`, [`ci.yml`](.github/workflows/ci.yml), [`w6.tftest.hcl`](infra/targets/gcp-gke/tests/w6.tftest.hcl)). The new `terraform-test` job plans the staging profile with mock providers and module overrides, so it needs no credentials and no state. Its 10 runs check what each inference backend deploys (no vLLM, advisor or NeMo server under `none`; vLLM and the selected advisor under `vllm`) and that the plan refuses `external`, any `enable_vllm`, `vllm` without a GPU pool, and the NeMo server without `vllm`. The job is not `continue-on-error`, so it can fail (POAM-2026-150). Two mutations of `main.tf` were checked to fail it.
- **`CAGE_INFERENCE_BACKEND` chooses the inference backend independently of jurisdiction: `none`, `external` or `vllm`** (`feat(gateway)`, [`inference_backend.py`](src/gateway/governance/inference_backend.py)). Under `none` the gateway starts with no `VLLM_*` settings and builds no NeMo rails, and every model-dependent path refuses with its own reason code instead of admitting or reaching for a default URL.
  - Content safety answers `BLOCKED` with `CONTENT_SAFETY_NO_INFERENCE_BACKEND` ([`mcp_tool_server.py`](src/gateway/server/mcp_tool_server.py), [`semantic_rail_factory.py`](src/gateway/governance/semantic_rail_factory.py)).
  - The inference proxy answers 503 with `INFERENCE_BACKEND_NONE` ([`inference_proxy.py`](src/gateway/server/inference_proxy.py)).
  - Consensus at or above its threshold is a DENY with `CONSENSUS_NO_INFERENCE_BACKEND`, reached before any critic is consulted. Below the threshold it skips, as it does with a backend ([`engine.py`](src/gateway/governance/consensus/engine.py)).
  - The compliance bridge records the remediation advisory as `NOT_PERFORMED` with `INFERENCE_BACKEND_NONE` ([`audit_workflow.py`](src/compliance_bridge/audit_workflow.py)).

  An unknown value fails startup. Unset keeps the behaviour from before the setting existed: a backend is required. No infrastructure profile changes here; choosing `none` per profile is a separate change.
- **A pre-merge double-check of every required status check** (`feat(compliance)`, [`check_pr_mergeable.sh`](scripts/check_pr_mergeable.sh)). The script reads the required checks GitHub applies to the base branch, verifies each on the exact head SHA through the REST check-runs and commit-status APIs, fails closed on an empty rule set or any API error, and posts the result on the pull request.

### Changed

- **On GKE, `inference_backend` decides what is deployed: staging runs the governance core with no model by default, and `external` is compose-only (`POAM-2026-136`)** (`refactor(infra)!`, [`main.tf`](infra/targets/gcp-gke/main.tf), [`variables.tf`](infra/targets/gcp-gke/variables.tf), [`staging.tfvars`](infra/targets/gcp-gke/staging.tfvars)).
  - `inference_backend` replaces `enable_vllm` and sets `CAGE_INFERENCE_BACKEND` on the gateway and the compliance bridge. Under `"none"`, the default and staging's setting, no vLLM, no advisor in either runtime and no NeMo server are deployed, so nothing is left pointing at a model service that does not exist. Under `"vllm"` the vLLM deployments and the advisor are deployed. `"external"` is refused: the cluster denies external egress by default, and opening it for the agent would weaken that control.
  - Staging keeps its GPU pool at min 0 / max 2 / initial 0 in one zone (`us-central1-a`), so switching to `"vllm"` is a variable change and an apply. The three-zone list it had tripled those counts.
  - `enable_nemo_guardrails` defaults to `false`. A plan guard refuses `"vllm"` without a GPU pool, and the NeMo server without `"vllm"`.

### Breaking Changes

#### PR A — Capability-Driven Tier Dispatch

- **Legacy Inline Dispatch Removed** — The inline consensus gate, causal gatekeeper, FRIA/normative provider, and CBF/fiscal blocks have been deleted from `SymbolicGovernor._run_checks()`. - **RefusalReceipt Schema v3** — `RefusalReceipt.schema_version` default changed from "v1" to "v3". Schema v3 includes the `tier_failures` tuple field for multi-tier governance. The proof_hash computation now includes tier_failures when schema_version != "v1". Existing receipt consumers must handle both v1/v2 legacy receipts and v3 receipts (`feat(governance)!`).

These null objects explicitly deny all requests rather than silently failing or allowing. Plugins must call `install_domain_components()` to install real implementations (`refactor(governance)!`).
